## 一、目标

交付**一个 HTML 文件**，双击即玩，无任何外部依赖。里面是**故事线一（脊髓损伤）的完整一遍**：
第 1/2/3 节 + 危机关怀分支 + 终章，全部可点通。

故事线二（截肢）、故事线三（慢性疼痛）先在选线页占位（剪影 + 「即将推出」），
但**数据结构与引擎必须已经支持它们**——写第二条线时只加一份内容数据，不改引擎。

## 二、为什么这个顺序

存档里的原话是对的：**先把故事线一做成能双击玩的 HTML，实际玩一遍再铺另外两条。**

- 内容数据格式只有被引擎真正跑过一遍，才知道哪些字段是多余的；
- 剧本读起来和玩起来是两种感觉——先跑一条，避免同样的毛病被复制到三条线上；
- 单文件交付物是硬要求，越早锁死"没有构建步骤"这个约束，后面越不会返工。

## 三、工程结构（源码分开写，产物是一个文件）

单文件交付 ≠ 单文件开发。源码按职责拆开，产出一个 HTML：

```
src/
  shell.html        # 骨架：<style> + <body> + 挂载点 + <!--INJECT:x-->
  styles.css        # 全部样式（设计令牌在顶部 :root）
  sprites.json      # 像素物件（由 tools/extract-sprites.mjs 从方案B 抽出，不手打）
  sprites.js        # 立绘 + 场景时段变体（补方案 B 没画的东西）
  story.js          # 内容数据：故事线一全脚本
  ui.js             # 渲染：标题页 / 选线页 / 对话 / 日记 / 科普卡 / 督导笔记 / 终章
  engine.js         # 状态机：节点推进、选择记录、存档、危机分支
build.mjs           # 把上面几块按顺序注入 shell.html → 根目录 心理咨询.html
tools/
  extract-sprites.mjs  # 从 docs/mockups/方案B-内联SVG.html 抽 SPRITES → src/sprites.json
tests/
  check-game.mjs       # 无头自检：语法、跳转、热线次数、红线、存档
```

产物：**`心理咨询.html`**（根目录，唯一交付物）。

## 四、实施顺序

| # | 步骤 | 产出 | 验收 |
|---|---|---|---|
| 1 | 写设计文档 | `docs/design/2026-09-27-心理咨询页游-设计文档.md` | 含页面流程、数据格式、存档结构、验收标准 |

## 五、要守住的红线（开发时逐条核）

出自 `docs/项目存档-Notion.md` 第七节，实现层面的落点见设计文档末节。

- 危机处理**写死在脚本数据里**，不经过任何模型判断（本作已无模型，天然满足）
- 免责声明 + 热线（12356 / 010-82951332 / 120）出现 **≥3 处**：标题页、游戏内常驻入口、终章资源卡
- 所有选项**都能继续**，没有"答错就卡死"
- 督导笔记是教学层，**不扣分、不评判玩家**
- 危机筛查「不问」**不惩罚**，但存档留痕、终章提示
- 人物、机构、事件全部虚构；正文不出现真实单位名

## 六、明确不做的

- 不装 Node 依赖、不引入构建工具链（`build.mjs` 只用 `node:fs`）
- 不做 AI 自由对话、不做后端、不做 API Key
- 不做游戏引擎
- 不做音频（课程版先不放，避免素材版权与体积问题）

## 七、风险

| 风险 | 应对 |
|---|---|
| 单文件变太大、以后改不动 | 源码拆文件 + `build.mjs` 合并；改内容只碰 `src/story.js` |
| 引擎写死成只能跑一条线 | 内容全部是数据；引擎不认识"脊髓损伤"，只认识 `say` / `choice` / `card` |
| 玩起来发现台词别扭 | 这是**预期内**的，先跑通一条再改；改台词只动 `src/story.js` |
| 浏览器直接打开 file:// 被限制 | 不用 fetch / 不用 ES module / 不用外部字体文件；全部内联 |
